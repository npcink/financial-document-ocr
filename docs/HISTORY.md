# 项目沿革与权威边界

本文记录 Financial Document OCR 从内部原型迁移为独立公开项目的过程，并说明哪些资料可以作为当前事实依据。功能、配置和安全要求始终以当前仓库的代码和正式文档为准。

## 时间线

### 内部原型阶段

项目最初在内部混合文档仓库中验证财务图片和文档的批量 OCR、字段提取、人工审阅与表格导出流程。这个阶段曾尝试不同的 OCR、语言模型、页面结构和部署方式；相关实施计划只反映当时的探索，不构成当前功能、模型或兼容性承诺。

### 2026-07-15：独立维护

项目从内部混合仓库迁出，建立独立源码目录和维护边界。迁移的目标是让源码、项目文档和依赖配置可以独立演进，同时把密钥、数据库、上传件、导出件、日志及真实业务材料留在运行环境和私密运维边界中。

这一天对应项目功能线的 `3.0.0` 整理节点，但当时的内部历史和运行资料没有直接作为公开 Git 历史发布。

### 2026-07-21：公开发布

项目使用经过白名单整理的源码建立新的干净 Git 历史，并完成以下公开发布工作：

- 采用 `GPL-3.0-only` 项目许可证；
- 使用宽松许可的 `pypdfium2`/PDFium 处理 PDF 渲染，并记录第三方许可；
- 明确云端模型的数据传输、本地 Ollama 的实际网络边界，以及 `X-Session-ID` 不属于身份认证；
- 加固上传文件名、任务标识和数据目录的路径边界；
- 确认 Git 和源码包不包含密钥、数据库、上传件、导出件、日志、备份或真实业务样例；
- 创建并发布 `v3.0.0` 标签。

公开发布核验记录见 [PUBLIC_RELEASE_CHECKLIST.md](PUBLIC_RELEASE_CHECKLIST.md)。

## 稳定下来的设计方向

内部探索经过收敛后，当前项目采用以下边界：

1. Vue 3 前端负责上传、任务状态、结果审阅、重试与导出；
2. FastAPI 后端负责文件接入、处理流水线、任务状态和导出接口；
3. SQLite 保存运行任务和结构化结果，但不进入 Git 或普通源码备份；
4. 云端与本地模式共享处理流程，具体模型和服务地址通过环境配置选择；
5. OCR 和模型输出必须经过人工审阅，不能直接作为记账、付款、报税或合规结论；
6. 默认部署面向本机或受信任网络，公网部署需要独立的 HTTPS、认证、授权、日志和限流层。

当前架构见 [ARCHITECTURE.md](ARCHITECTURE.md)，安全边界见 [../SECURITY.md](../SECURITY.md)。

## 文档权威顺序

遇到内容冲突时，按以下顺序判断：

1. 当前仓库默认分支的代码、README、SECURITY 和 `docs/`；
2. 当前发布标签及其发布检查记录；
3. 实际部署环境的配置和运行状态；
4. 私密运维资料中的部署证据；
5. 原内部混合仓库中的迁出指针或历史记录。

原内部仓库不再是功能、模型、版本、部署命令或安全边界的事实来源。

## 不应恢复的历史内容

以下内容没有迁入当前仓库，也不应从旧历史恢复后继续维护：

- 旧的实施计划、临时学习笔记和已过时的完成清单；
- 旧模型名称、内部地址、本机绝对路径和特定主机配置；
- `.env`、API Key、数据库及其 WAL/SHM 文件；
- 上传件、导出表格、OCR 原文、真实财务字段和运行日志；
- 可由当前源码、锁文件和构建流程重新生成的依赖或产物。

源码、密钥与运行数据的正式决定见 [ADR-001](decisions/001-source-runtime-data-separation.md)。
